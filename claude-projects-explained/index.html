Claude Projects Explained: How to Organize Long Work

By the Noryvello team · Published 18 November 2026 · Updated 18 November 2026

A Claude Project is a folder for one piece of long work: it holds your files, your instructions, and your chats in one place, so every new chat in the Project starts with the context already there. This guide explains what Projects are, how to add knowledge files and custom instructions, and when a Project helps and when a plain chat is enough.

The problem Projects solve is repetition. Without them, every new chat starts blank. If you are writing a book, researching a topic, or running a repeated task, you end up pasting the same background into every conversation: the same files, the same instructions, the same explanation of what you are doing. A Project removes that repetition by keeping the background in one place that every chat in the Project can use.

Think of a Project as a desk drawer for one job. Inside the drawer are the reference files, a note about how you want the work done, and all the conversations about that job. When you sit down to work, everything is already there. The rest of this guide explains how to set that drawer up and how to keep it useful.

Project features, limits, and sharing options vary by plan and change between updates, so the steps in this guide are described in general terms. If something looks different on your screen, check the current version. Never upload files with personal details, account numbers, or other people's private information to a Project.

What Projects are

A Project is a workspace inside Claude for one ongoing piece of work. It has three parts: knowledge files, custom instructions, and the chats that belong to it. Knowledge files are the documents you upload so Claude can refer to them. Custom instructions are standing directions, such as the tone to use or the audience to write for. Chats inside the Project can use both, which means each new conversation starts with the background already in place.

Projects are best for work that stretches over days or weeks, or for tasks you repeat often. Writing a book, planning a course, researching a topic, or preparing a regular report are all good fits. The common thread is that the work has background material and standing rules that would be tedious to repeat in every chat. If a task has no background and no rules, it probably does not need a Project.

Adding knowledge files

Knowledge files are the reference material for your Project: documents, notes, spreadsheets, or any file the work depends on. Once a file is added, chats inside the Project can read it and answer questions about it, quote from it, and use it as the basis for drafts. This is what makes a Project feel different from a plain chat: the chatbot already knows your material.

Add files with a light hand. A small set of relevant files works better than a large pile. Before adding a file, ask whether the work actually needs it. Remove files that are out of date, and replace a draft with the final version when one exists. If a file contains anything private, clean it first or leave it out entirely, since anything in a Project can be read by every chat inside it.

Custom instructions

Custom instructions are standing directions that apply to every chat in the Project. They are the place to say things you would otherwise repeat: the tone to use, the audience to write for, the format you prefer, or the rules to follow. A good set of instructions is short and specific. "Write in a plain, friendly style for adult beginners. Use short paragraphs and everyday words. Never invent facts or statistics." is a better set of instructions than a long list of vague wishes.

Instructions work best when they describe outcomes rather than processes. Say what a good answer looks like, not how Claude should think. It also helps to include anything Claude should never do, such as inventing quotes or using jargon. You can change the instructions at any time, and it is worth revising them after a few chats, once you see which directions are actually being followed and which are being ignored.

When Projects help

Projects help most with long, messy work. Writing a book is the classic example: the Project holds your notes, your outline, and your drafts, and every chat knows the characters, the setting, and the style. Research is another: the Project holds your sources, and each chat can compare them, summarize them, or find a specific claim. Repeated tasks are a third: if you write the same kind of report every month, a Project can hold the template, the standing instructions, and last month's version.

The test is simple. If you find yourself pasting the same background into chat after chat, that background belongs in a Project. If you keep re-explaining the same rules, those rules belong in the custom instructions. A Project earns its place the second time you would otherwise have repeated yourself.

When a plain chat is enough

Not every task needs a Project, and making one for a small task adds work instead of saving it. A one-off question, a single email, a quick brainstorm, or a short explanation are all better in a plain chat. Setting up a Project for those is like opening a filing cabinet to store one letter.

A plain chat is also the right choice when you are exploring and do not yet know what the work will become. Start in a plain chat, see where the conversation goes, and only create a Project once the task has a shape: files worth keeping, rules worth repeating, and more chats to come. Many good Projects start as a plain chat that grew into something bigger.

Setting up your first Project

Setting up a Project takes a few minutes. Create the Project and give it a clear name, one that tells future-you what it is for. Then add the knowledge files the work needs, starting with the most important one or two. Then write the custom instructions: a few sentences covering tone, audience, format, and anything to avoid. Then start a chat inside the Project and test it with a real question.

The test chat matters. Ask something that needs the files, such as "summarize the main argument of the document I uploaded" or "draft the next section in the style of the notes." If the answer shows that Claude is using the files and following the instructions, the Project is set up well. If it is not, the fix is usually simpler instructions or fewer, better-chosen files.

Keeping a Project tidy

A Project is only as good as its contents, and contents go stale. Set a habit of tidying it every so often: remove files that are out of date, replace drafts with final versions, and update the instructions to match what you have learned. A Project with old files and forgotten instructions will give answers based on material you no longer trust.

It also helps to keep the chat list tidy. Give important chats a clear purpose, and delete the ones that were dead ends. When a Project is finished, decide what to do with it: keep it as a record, or delete it if the work is done and the files live elsewhere. A tidy Project stays useful; a neglected one becomes a drawer full of things you no longer recognize.

Questions people ask

Do I need a paid plan to use Projects?

Availability and limits vary by plan and change over time, so check the current plan details for your account. In general, the idea is the same on every plan: a Project is a folder that keeps files, instructions, and chats for one piece of work together.

How many files can I add to a Project?

Limits on the number and size of files exist and change over time. The practical advice is to add only the files the work actually needs. A small set of relevant files works better than a large pile of maybe-useful ones.

Can I share a Project with someone else?

Sharing options vary by plan and change over time. Before sharing anything, check what the other person will be able to see, and remove any file that contains private information. If you are unsure, share the finished text instead of the whole Project.

What happens to my chats inside a Project?

Chats started inside a Project stay in that Project and can use its knowledge files and custom instructions. That is the main benefit: each new chat in the Project starts with the context already in place, instead of starting from nothing.

Can I move a chat into a Project?

In general, chats can be organized into Projects from the chat list, though the exact steps depend on the current version. If you cannot move a chat, start a new chat inside the Project and paste the important context into it.
